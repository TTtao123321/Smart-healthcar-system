# 智慧医疗助手Agent — 产品需求文档（PRD）

> **文档版本**：v1.0  
> **编写日期**：2026-06-17  
> **目标读者**：产品经理、技术团队、运营团队  
> **核心定位**：面向患者的医院服务智能入口，不做医疗诊断，只做就医流程服务

---

## 1. 项目背景与目标

### 1.1 背景

当前患者就医面临信息不对称、流程复杂、等待时间长等痛点。医院已具备科室、诊室、医生信息及当日排班等基础数据，需构建一个面向患者的智能服务入口，提升就医体验与运营效率。

### 1.2 核心约束

- **无法使用医疗垂直领域大模型**：不能提供疾病诊断、治疗方案、用药建议等专业医疗功能
- **合规要求**：严格遵守《互联网诊疗管理办法》《生成式人工智能服务管理暂行办法》等法规
- **安全底线**：所有医疗决策必须转交真人医生，Agent仅做信息导航与服务引导

### 1.3 产品目标

| 目标 | 指标 | 目标值 |
|------|------|--------|
| 提升挂号效率 | 平均挂号耗时 | 降低50% |
| 减少导医台压力 | 人工咨询量 | 降低30% |
| 改善患者体验 | 患者满意度 | ≥4.5/5.0 |
| 降低爽约率 | 预约爽约率 | 降低20% |

## 2. 产品定位

> **一句话定位**：做"智能导诊员"，而非"AI医生"

| 角色 | 职责边界 | 示例 |
|------|----------|------|
| **智能导诊员（Agent）** | 信息查询、流程引导、事务办理 | "消化内科在3楼，今日有3位医生出诊" |
| **AI医生（禁止）** | 疾病诊断、用药建议、报告解读 | "您的头痛可能是偏头痛，建议服用XXX" |
| **真人医生（兜底）** | 所有医疗决策、诊断、治疗 | 复杂问题一键转人工 |

## 3. 用户画像

### 3.1 主要用户：患者/家属

- **年龄分布**：18-70岁，以中老年为主
- **核心诉求**：快速找到对的科室、减少等待、了解就诊流程
- **使用场景**：院前（挂号）、院中（导航/候诊）、院后（随访）

### 3.2 次要用户：医院运营人员

- 维护FAQ知识库、医生标签、症状-科室映射规则
- 查看服务数据、优化运营策略

## 5. 功能详细设计

### 5.1 智能就医引导（导航类）

#### 5.1.1 症状→科室匹配（规则分诊）

**功能描述**：基于患者输入的症状关键词，通过规则引擎匹配推荐科室，辅助患者挂号。

**技术方案**：
- 规则引擎：关键词→科室映射表（由医院运营维护）
- 多轮澄清：当症状模糊时，通过追问缩小范围

**映射表示例**：

| 症状关键词 | 推荐科室 | 澄清问题 | 备注 |
|-----------|---------|---------|------|
| 肚子疼 | 消化内科/普外科 | 疼痛部位？是否伴随呕吐？ | 上腹痛→消化内科；右下腹痛→普外科 |
| 头疼 | 神经内科/耳鼻喉科 | 头痛部位？伴随症状？ | 偏头痛→神经内科；鼻塞伴头痛→耳鼻喉科 |
| 胸闷 | 心内科/呼吸内科 | 是否活动后加重？ | 活动后加重→心内科；咳嗽伴胸闷→呼吸内科 |

**交互流程**：

```
患者："我最近头疼"
Agent：您好，头痛可能涉及多个科室，为了帮您更准确挂号，请补充：
       1. 头痛部位（前额/两侧/后脑勺/全头）？
       2. 是否伴随发热、呕吐、视力模糊？
       3. 是否有外伤史？

[患者选择：两侧，无其他症状]
Agent：根据您的描述，建议优先考虑神经内科或耳鼻喉科。
       ⚠️ 注意：这仅为方便您挂号，具体诊断需医生面诊。
       [展示当日神经内科和耳鼻喉科出诊医生列表]
```

**安全声明**：
- 每次分诊结果必须附带免责声明："仅为方便挂号，不能替代医生面诊"
- 分诊结果仅展示科室名称，不做疾病名称推测

---

#### 5.1.2 科室职能介绍

**功能描述**：用通俗语言解释各科室诊疗范围，帮助患者理解"该挂什么科"。

**内容来源**：医院运营人员维护的标准化介绍文案

**示例**：

| 科室 | 通俗介绍 | 常见症状 |
|------|---------|---------|
| 内分泌科 | 主要调节身体"激素平衡"，如血糖、甲状腺、骨质疏松等 | 多饮多尿、体重异常变化、手脚麻木 |
| 消化内科 | 看"从嘴到肛门"的消化道问题，以及肝脏、胆囊、胰腺 | 胃痛、腹泻、便秘、黄疸 |
| 心内科 | 专看心脏和血管问题，如高血压、冠心病、心律失常 | 胸闷、心悸、头晕、活动后气促 |

---

#### 5.1.3 就诊流程指引

**功能描述**：根据患者当前状态（未挂号/已挂号/候诊中/检查中），提供全流程导航。

**流程节点**：

```
挂号 → 签到（到达医院） → 候诊 → 就诊 → 检查/检验 → 取报告 → 复诊/取药 → 离院
```

**状态感知**：
- 未挂号：推荐科室→展示医生→跳转挂号
- 已挂号未签到：提醒签到地点、截止时间
- 候诊中：实时叫号进度、预计等待时间
- 检查中：检查地点导航、注意事项提醒
- 待取报告：报告出具时间预估、查询入口

---

#### 5.1.4 院内导航

**功能描述**：基于患者当前位置和目的地诊室，生成图文导航路线。

**数据源**：医院诊室位置信息（楼层、区域、房间号）

**输出示例**：

```
您当前位置：门诊大厅1楼
目的地：3楼B区 消化内科诊室

路线：
1. 从门诊大厅乘坐电梯至3楼
2. 出电梯右转，沿B区指示牌前行50米
3. 消化内科诊室位于B区通道尽头（房间号：302-305）

[图文地图]
```

### 5.2 医生资源查询（信息检索类）

#### 5.2.1 医生信息查询

**功能描述**：展示医生基本信息、擅长方向、出诊时间。

**展示字段**：

| 字段 | 来源 | 说明 |
|------|------|------|
| 姓名 | 医院HIS系统 | - |
| 职称 | 医院HIS系统 | 主任医师/副主任医师/主治医师 |
| 科室 | 医院HIS系统 | - |
| 擅长方向 | 医院运营维护标签 | 如"高血压、冠心病、心律失常" |
| 医生简介 | 医院运营维护 | 简短介绍，不做AI生成 |
| 出诊时间 | 排班系统 | 当日及未来7天 |
| 剩余号源 | 挂号系统 | 实时同步 |

**安全约束**：
- 擅长方向仅为医院维护的标签，Agent不做解读或扩展
- 不回答"这位医生水平怎么样"等主观评价问题

---

#### 5.2.2 实时排班查询

**功能描述**：查询当日及未来7天医生出诊安排与号源状态。

**查询维度**：
- 按科室查询："心内科明天有哪些医生出诊？"
- 按医生查询："张医生的出诊时间？"
- 按日期查询："本周五上午有哪些专家？"

**状态标识**：

| 状态 | 标识 | 操作 |
|------|------|------|
| 有号源 | 绿色"可预约" | 展示预约入口 |
| 号源紧张 | 黄色"余号少" | 提示尽快预约 |
| 已满号 | 灰色"已满" | 推荐同科室其他医生 |
| 停诊 | 红色"停诊" | 展示停诊原因（如有） |

---

#### 5.2.3 医生推荐（规则匹配）

**功能描述**：基于患者症状关键词与医生标签的规则匹配，推荐可能合适的医生。

**匹配逻辑**：

```
患者输入关键词（如"高血压"）
  ↓
与医生标签库进行匹配（精确匹配 > 同义词匹配）
  ↓
按匹配度排序，展示Top 3-5位医生
  ↓
附带声明："推荐结果基于标签匹配，请结合医生排班时间选择"
```

**约束条件**：
- 仅做信息检索匹配，不做医学适合度判断
- 必须展示"患者也可自行选择其他医生"

---

### 5.3 就诊事务办理（操作类）

#### 5.3.1 智能挂号/预约

**功能描述**：根据患者选择，自动跳转对应科室号源，支持自然语言预约。

**支持指令示例**：

| 患者输入 | Agent解析 | 执行动作 |
|---------|----------|---------|
| "我想挂明天上午心内科" | 时间：明天上午；科室：心内科 | 展示心内科明日上午出诊医生列表 |
| "帮我约张医生下周三的号" | 医生：张XX；时间：下周三 | 展示该医生下周三号源 |
| "消化内科还有号吗" | 科室：消化内科；时间：默认当日 | 展示消化内科当日剩余号源 |

**挂号流程**：

```
患者选择科室/医生 → 选择时间段 → 确认就诊人信息 → 支付 → 预约成功
                      ↓
              推送预约确认短信/微信
```

---

#### 5.3.2 候诊进度查询

**功能描述**：实时同步叫号系统，推送候诊进度与预计等待时间。

**展示内容**：

```
当前就诊科室：消化内科（3楼B区302诊室）
您的排队序号：28号
当前叫号：25号
前面等待：3人
预计等待时间：约15分钟

[实时刷新按钮]  [到号提醒开关]
```

**推送策略**：
- 前面剩余5人时：推送"即将到您，请前往诊室门口等候"
- 叫号到本人时：推送"轮到您就诊了，请进入302诊室"

---

#### 5.3.3 报告查询

**功能描述**：对接LIS（检验）/PACS（检查）系统，患者可查询报告出具状态。

**查询范围**：
- 检验报告：血常规、尿常规、生化等
- 检查报告：CT、MRI、B超、X光等

**展示内容**：

```
报告名称：血常规（五分类）
送检时间：2026-06-17 09:30
报告状态：已出具
出具时间：2026-06-17 11:20

[查看报告]  [下载PDF]
```

**安全约束**：
- 仅提供报告状态与原始数据展示
- **禁止解读报告内容**：患者询问"这个指标高怎么办"时，回复"请携带报告咨询您的主治医生"

---

#### 5.3.4 缴费引导

**功能描述**：生成待缴费清单，提供支付入口链接。

**展示内容**：

```
待缴费项目：
1. 挂号费：15元（已支付）
2. 检查费：CT平扫 280元 [去支付]
3. 药费：阿莫西林胶囊等 45.6元 [去支付]

合计待支付：325.6元

[一键支付]  [医保结算]
```

---

### 5.4 诊后服务管理（延伸类）

#### 5.4.1 用药提醒

**功能描述**：患者手动录入医嘱用药信息，Agent定时提醒。

**录入字段**：
- 药品名称（手动输入）
- 服用剂量（如"每次1片"）
- 服用时间（如"每日3次，早中晚饭后"）
- 提醒方式（APP推送/短信/微信）

**提醒示例**：

```
⏰ 用药提醒
药品：阿莫西林胶囊
剂量：每次1粒（0.25g）
时间：饭后服用

[我已服用]  [稍后提醒]
```

**安全约束**：
- 仅提供闹钟提醒功能，不解释药理、不回答用药疑问
- 用药疑问统一回复"请咨询开药医生或药师"

---

#### 5.4.2 复诊提醒

**功能描述**：基于医生设定的复诊周期，自动提醒患者预约复诊。

**触发条件**：
- 医生在系统中标记"建议2周后复诊"
- 患者本次就诊完成后自动启动倒计时

**提醒示例**：

```
📅 复诊提醒
您于2026-06-03就诊，医生建议2周后复诊。
复诊截止时间：2026-06-17

[立即预约复诊]  [我已复诊]  [推迟提醒]
```

---

#### 5.4.3 满意度评价

**功能描述**：就诊完成后推送评价问卷，收集患者反馈。

**评价维度**：
- 挂号便捷性（1-5星）
- 候诊体验（1-5星）
- 医生服务态度（1-5星）
- 整体满意度（1-5星）
- 开放式建议（选填）

## 6. 安全护栏设计

### 6.1 敏感词拦截

**拦截场景**：患者输入包含医疗诊断类请求时，自动拦截并引导。

| 触发关键词 | 拦截响应 |
|-----------|---------|
| "诊断""治疗方案""吃什么药""严重吗" | "我无法提供医疗建议，请直接咨询医生" |
| "这个指标正常吗""报告有什么问题" | "我无法解读医疗报告，请携带报告咨询您的主治医生" |
| "我得了什么病""这是什么症状" | "我无法进行疾病诊断，建议您尽快到院就诊" |

**技术实现**：
- 关键词黑名单（正则匹配）
- 通用LLM系统Prompt中明确禁止回答医学诊断类问题

---

### 6.2 异常识别与应急处理

**高危关键词识别**：

| 关键词 | 响应策略 |
|--------|---------|
| "自杀""自残""不想活了" | 立即推送心理危机干预热线，同步通知人工客服 |
| "剧烈疼痛""大出血""昏迷""呼吸困难" | 立即推送急诊通道信息，建议拨打120 |
| "胸痛""胸闷"（中老年患者） | 提示"如症状严重请立即前往急诊或拨打120" |

**技术实现**：
- 关键词实时监测
- 触发后自动转人工客服或推送预设应急信息

---

### 6.3 边界声明

**声明位置**：
- 首次对话时自动发送边界声明
- 每次涉及症状/健康相关话题时重复声明
- 设置页面常驻声明入口

**声明文案**：

```
⚠️ 重要提示
我是XX医院智慧服务助手，仅提供就医流程引导、信息查询等服务。
我无法进行疾病诊断、提供治疗方案或用药建议。
如有身体不适，请尽快到院就诊或咨询专业医生。
```

---

### 6.4 人工兜底

**兜底机制**：
- 所有对话界面常驻"转人工客服"按钮
- 当Agent连续3次无法理解用户意图时，自动提示转人工
- 涉及投诉、纠纷、复杂政策问题时，主动建议转人工

### 7.2 关键技术选型

| 功能模块 | 技术方案 | 选型理由 |
|---------|---------|---------|
| 自然语言理解 | 通用LLM（如GPT-4/Claude）+ 严格Prompt约束 | 理解患者口语化表达，但需严格限制回答边界 |
| 症状分诊 | 规则引擎（关键词→科室映射表） | 可控、可解释、可审计，满足医疗合规 |
| 医生推荐 | 标签匹配算法（TF-IDF/余弦相似度） | 基于结构化标签匹配，不做AI主观判断 |
| 多轮对话 | 对话状态机（FSM） | 管理挂号、分诊等复杂多轮流程 |
| 知识库问答 | Elasticsearch + 运营维护FAQ | 医院政策、流程类问题标准化回答 |
| 实时推送 | WebSocket + 消息队列 | 候诊叫号、用药提醒等实时通知 |

## 9. 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 患者误将Agent当医生 | 延误病情、医疗纠纷 | 强制边界声明、敏感词拦截、人工兜底 |
| 分诊规则不准确 | 挂错科室、患者投诉 | 多轮澄清机制、规则持续优化、满意度反馈 |
| 系统故障导致服务中断 | 患者无法挂号 | 降级方案（跳转传统挂号页面）、故障告警 |
| 患者隐私数据泄露 | 合规风险、信任危机 | 数据脱敏、权限控制、审计日志 |
| 通用LLM生成违规医疗建议 | 合规风险 | 严格Prompt约束、输出审查层、黑名单拦截 |
