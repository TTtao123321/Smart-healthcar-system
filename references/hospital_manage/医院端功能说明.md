# hospital_manage 端功能说明

## 1. 文档目的

本文档用于说明 `hospital_manage` 端当前已经实现的前端功能范围，帮助项目成员快速了解医院管理后台的现状、已支持的业务流程、对应页面入口，以及当前仍处于原型或预留状态的能力。

说明范围以 `hospital_manage_frontend/` 当前代码实现为准，不等同于产品规划范围，也不默认代表后端所有能力都已完整联调。

## 2. 系统定位

`hospital_manage` 端是智慧医院管理系统的医院后台管理端，主要面向医院管理员、医护人员和运营管理角色，承担以下职责：

- 医院组织信息维护
- 医生与患者业务管理
- 门诊排班与出诊安排
- 系统账号、角色、权限管理
- 医疗助手入口展示

前端主工程路径：

- `hospital_manage_frontend/`

关键入口文件：

- `hospital_manage_frontend/src/main.js`
- `hospital_manage_frontend/src/router/index.js`
- `hospital_manage_frontend/src/views/main.vue`

## 3. 技术与运行特征

当前医院端前端基于以下技术栈实现：

- `Vue 3`
- `Vite`
- `Element Plus`
- 自定义 `$http` Ajax 封装

当前代码中可确认的运行特征如下：

- 后端接口基础地址为 `http://localhost:9091/hms/`
- 登录后会将 `token`、`permissions`、`name`、`roleNames` 存入本地缓存
- 页面访问依赖路由守卫校验登录态
- 菜单和按钮显示依赖权限码判断
- 主界面支持多标签页后台工作区

## 5. 已实现功能详情

### 5.1 登录、会话与后台框架

当前已实现的基础能力包括：

- 用户名密码登录
- 登录成功后写入本地登录信息
- 路由守卫校验未登录跳转登录页
- 基于权限码控制菜单展示
- 顶部导航栏显示当前用户
- 支持退出登录
- 支持修改密码
- 支持左侧菜单折叠
- 支持多标签页切换与关闭

可确认的特点：

- 登录页已经具备真实接口调用能力，不是静态页面
- 后台框架已经满足日常管理系统连续操作需求
- 权限控制分为登录态控制和菜单显示控制两层

### 5.2 组织管理

#### 5.2.1 医疗科室管理

当前支持：

- 科室分页查询
- 按条件筛选查询
- 查看科室列表
- 新增科室
- 编辑科室
- 删除科室

页面覆盖的字段和信息包含：

- 科室名称
- 推荐级别
- 门诊类型
- 其他基础科室信息

整体状态：

- 该模块已具备完整 CRUD 能力
- 适合作为医院组织主数据维护入口使用

#### 5.2.2 医疗诊室管理

当前支持：

- 诊室分页查询
- 按所属科室筛选
- 查看诊室列表
- 新增诊室
- 编辑诊室
- 删除诊室

整体状态：

- 与科室管理形成上下级组织维护关系
- 已具备完整 CRUD 能力

### 5.3 医护管理

#### 5.3.1 医生管理

当前支持：

- 医生分页查询
- 按条件筛选医生
- 查看医生详情
- 新增医生
- 编辑医生
- 删除医生
- 医生状态切换
- 医生头像上传

页面已覆盖的业务信息包括：

- 医生基础资料
- 所属科室/诊室信息
- 医生详情展开查看
- 医生状态维护

整体状态：

- 已具备较完整的医生档案维护能力
- 能支撑诊费设置、排班、患者接诊等下游业务

#### 5.3.2 患者管理

这是当前医院端最完整的业务闭环模块之一。

当前支持：

- 患者挂号记录分页查询
- 按姓名、性别、科室、诊室、医生、状态等条件筛选
- 标记患者已接诊
- 查看患者详情
- 编辑患者资料
- 写病历
- 查看病历
- 开处方
- 删除处方
- 结束就诊

其中已经形成的核心业务链路如下：

1. 查询待处理患者挂号记录
2. 医生执行接诊
3. 填写病历
4. 自动更新挂号状态为已就诊
5. 查看历史病历详情
6. 基于病历开具处方
7. 支持处方删除
8. 结束本次就诊

页面中已覆盖的数据能力包括：

- 患者基础信息查看与修改
- 病史信息展示与编辑
- 病历主诉、现病史、体格检查、诊断、医嘱等记录
- 处方主表与药品明细录入
- 病历与处方联动查询

整体状态：

- 患者管理已经具备较完整的门诊接诊闭环
- 是当前最接近真实业务落地的模块之一

#### 5.3.3 诊费设置

当前支持：

- 医生诊费分页查询
- 查看医生诊费信息
- 调整医生诊费

整体状态：

- 能作为医生基础经营配置的一部分使用
- 功能相对聚焦，但已完成基础维护闭环

### 5.4 出诊管理

#### 5.4.1 门诊日程表

当前支持：

- 按科室查询
- 按日期查询
- 查看近 7 天排班信息
- 查看对应医生排班情况
- 从日程入口跳转到医生出诊表
- 新增排班

整体状态：

- 已形成从“门诊日程表”到“医生出诊表”的联动入口
- 适合做科室层面的排班总览

#### 5.4.2 医生出诊表

当前支持：

- 按诊室和日期查看医生出诊安排
- 查看具体时段排班
- 新增出诊安排
- 修改出诊安排
- 删除出诊安排

整体状态：

- 已形成更细粒度的医生排班管理能力
- 与门诊日程表组合后，可覆盖排班总览和明细维护两个层级

### 5.5 系统管理

#### 5.5.1 角色管理

当前支持：

- 查看角色列表
- 新增角色
- 编辑角色
- 删除角色

#### 5.5.2 用户管理

当前支持：

- 查看用户列表
- 新增用户
- 编辑用户
- 删除用户

#### 5.5.3 权限管理

当前支持：

- 查看权限列表
- 展示系统权限信息

#### 5.5.4 修改密码

当前支持：

- 当前登录用户修改密码

整体状态：

- 系统管理模块已覆盖后台基础 RBAC 管理能力
- 其中权限管理偏展示型，角色与用户管理更接近完整可用状态

### 5.6 医疗助手

当前页面已经具备较完整的前端交互界面，包括：

- 对话列表
- 新建会话
- 删除会话
- 输入消息
- 聊天消息展示
- 快捷提示词
- 助手欢迎语

当前页面呈现的助手能力包括：

- 医院信息问答入口
- 诊室查询入口
- 医生查询入口
- 患者查询入口

但从当前代码实现来看，现阶段状态更接近前端原型页：

- 发送消息后返回的是前端本地模拟回复
- 未看到真实大模型或检索接口调用
- 未形成与医院数据的真实联动查询链路

整体判断：

- UI 和交互骨架已完成
- 业务能力仍需后续接入真实服务

## 6. 权限与访问控制

当前医院端已接入基于权限码的前端控制逻辑。代码中可见的权限点包括但不限于：

- `ROOT`
- `ORG:SELECT`
- `MEDICAL:SELECT`
- `SCHEDULE:SELECT`
- `ROLE:SELECT`
- `USER:SELECT`
- `PERMISSION:SELECT`

当前权限控制主要体现在：

- 菜单是否显示
- 功能页面是否可进入
- 登录信息丢失时是否自动回到登录页

需要说明的是：

- 当前前端已经做了权限显示控制
- 更严格的数据权限和接口权限仍取决于后端实现

## 7. 当前实现程度总结

从当前前端实现情况来看，医院端可以分为两类成熟度：

### 7.1 已较完整落地的模块

- 登录与后台基础框架
- 医疗科室管理
- 医疗诊室管理
- 医生管理
- 患者接诊与病历处方闭环
- 诊费设置
- 门诊排班与医生出诊表
- 角色管理与用户管理

### 7.2 目前更偏原型或展示入口的模块

- 医疗助手

说明：

- 已完成界面和交互基础形态
- 尚未形成真实业务服务闭环

## 8. 适合后续补充的方向

如果后续继续完善 `hospital_manage` 端，建议优先关注以下方向：

- 补齐医疗助手的真实接口联调
- 增加更多业务状态说明和异常提示
- 梳理患者、医生、排班模块的字段字典与操作说明
- 将权限点、菜单、接口映射整理为统一配置文档

## 9. 文档结论

`hospital_manage` 端当前已经不是纯后台模板，而是具备实际业务承载能力的医院管理后台。尤其在组织管理、医生管理、患者接诊、排班管理和系统管理方面，已经形成较清晰的页面结构与业务闭环。

其中：

- `患者管理` 是当前业务完整度最高的模块之一
- `医疗助手` 当前仍处于前端原型和能力预留阶段

整体上，该端已经可以作为智慧医院管理系统的医院侧核心后台基础版本使用。
