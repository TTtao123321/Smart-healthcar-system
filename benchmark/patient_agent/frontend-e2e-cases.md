# patient_agent 前端页面操作流 E2E Case 清单

本清单用于人工回归和后续 Playwright/Vitest 页面级集成测试映射，覆盖 `patient_agent_frontend` 当前已经形成稳定交互闭环的页面旅程。

## 使用说明

- 执行顺序建议：先登录，再聊天，再线程恢复，再右侧栏挂号，再线程删除分支
- 每条 case 都包含页面入口、前置条件、操作步骤、期望结果、失败信号、关联能力基线 case
- 若页面行为与本清单不一致，应先核对实现变更，再决定更新 benchmark 还是修复代码

## Journey 1: 登录成功进入聊天页

- Case ID: `FE-E2E-001`
- 页面：`login_page -> chat_page`
- 优先级：`P0`
- 关联基线 case：`AUTH-001`、`AUTH-002`
- 前置条件：
  - 当前处于未登录状态
  - `/api/auth/send-sms` 与 `/api/auth/login` 可用
- 操作步骤：
  1. 输入合法手机号 `13800138000`
  2. 点击 `获取验证码`
  3. 输入返回的验证码
  4. 点击 `登录`
- 期望结果：
  - 登录成功后进入聊天页
  - 页面出现聊天输入框 `描述您的症状或健康问题...`
  - 当前 session 被写入本地缓存
- 失败信号：
  - 登录成功后仍停留在登录页
  - 没有进入聊天主界面
  - 当前 session 未落到本地缓存

## Journey 2: 登录页输入校验

- Case ID: `FE-E2E-002`
- 页面：`login_page`
- 优先级：`P0`
- 关联基线 case：`AUTH-003`
- 前置条件：
  - 当前处于未登录状态
- 操作步骤：
  1. 输入非法手机号，如 `123`
  2. 点击 `登录`
- 期望结果：
  - 出现 toast：`请输入正确的手机号码`
  - 不触发登录请求
- 失败信号：
  - 非法手机号仍可提交登录
  - 页面无提示

- Case ID: `FE-E2E-003`
- 页面：`login_page`
- 优先级：`P0`
- 关联基线 case：`AUTH-003`
- 前置条件：
  - 当前处于未登录状态
  - 已输入合法手机号
- 操作步骤：
  1. 输入合法手机号 `13800138000`
  2. 保持验证码为空
  3. 点击 `登录`
- 期望结果：
  - 出现 toast：`请输入验证码`
  - 不触发登录请求
- 失败信号：
  - 空验证码仍可提交
  - 页面无提示

## Journey 3: 聊天页恢复历史线程

- Case ID: `FE-E2E-004`
- 页面：`chat_page.left_panel`
- 优先级：`P0`
- 关联基线 case：`THREAD-001`、`THREAD-002`
- 前置条件：
  - 当前已登录
  - 本地无线程缓存或需要从服务端恢复线程
- 操作步骤：
  1. 进入聊天页
  2. 等待线程恢复逻辑完成
  3. 观察左侧历史会话列表
- 期望结果：
  - 左侧展示恢复出的历史线程
  - 恢复结果写回 patient-scoped 本地缓存
  - 如果当前 thread 不在恢复结果中，会清空当前 thread
- 失败信号：
  - 历史线程未显示
  - 恢复成功但未写回本地缓存
  - 当前 thread 指向不存在线程

## Journey 4: 在当前线程发送消息并消费 SSE

- Case ID: `FE-E2E-005`
- 页面：`chat_page.center_panel`
- 优先级：`P0`
- 关联基线 case：`STREAM-001`、`STREAM-002`
- 前置条件：
  - 当前已登录
  - 已存在当前线程，或页面允许自动创建新线程
- 操作步骤：
  1. 在输入框中输入 `继续刚才的话题`
  2. 点击 `发送`
  3. 观察消息区与流式更新
- 期望结果：
  - 当前线程追加用户消息和 AI 占位消息
  - 使用当前 `thread_id` 调用 `sendStream`
  - SSE 返回后，AI 回复逐步写入当前线程
- 失败信号：
  - 发送后消息未追加
  - 使用了错误的 `thread_id`
  - 流式完成后 AI 消息仍为空

## Journey 5: 页面刷新后继续在原线程续聊

- Case ID: `FE-E2E-006`
- 页面：`chat_page.left_panel + chat_page.center_panel`
- 优先级：`P0`
- 关联基线 case：`THREAD-003`
- 前置条件：
  - 当前 patient 已有本地线程缓存
  - 已记录当前 thread 为 `thread-1`
- 操作步骤：
  1. 首次进入页面并选中 `历史对话一`
  2. 模拟页面刷新或重新挂载
  3. 输入 `继续刚才的话题`
  4. 点击 `发送`
- 期望结果：
  - 页面刷新后仍然在 `thread-1` 上下文内
  - `sendStream` 使用 `thread-1`
- 失败信号：
  - 刷新后丢失当前 thread
  - 刷新后悄悄创建新线程

## Journey 6: 右侧栏加载失败 fallback 展示

- Case ID: `FE-E2E-007`
- 页面：`chat_page.right_sidebar`
- 优先级：`P1`
- 关联基线 case：`PROFILE-001`
- 前置条件：
  - 当前已登录
  - `patientApi.getSidebar()` 失败
- 操作步骤：
  1. 进入聊天页
  2. 模拟侧栏接口请求失败
  3. 观察右侧栏内容
- 期望结果：
  - 右侧栏仍展示 fallback 档案与排班数据
  - 页面不会因为侧栏接口失败而整体崩溃
- 失败信号：
  - 右侧栏空白
  - 页面报错导致聊天页无法使用

## Journey 7: 右侧栏选择医生并确认挂号

- Case ID: `FE-E2E-008`
- 页面：`chat_page.right_sidebar`
- 优先级：`P0`
- 关联基线 case：`SIDEBAR-001`、`REG-001`
- 前置条件：
  - 当前已登录
  - 右侧栏存在排班数据
- 操作步骤：
  1. 在右侧栏选择有医生数据的科室
  2. 点击 `预约挂号`
  3. 在确认弹窗中点击 `确认挂号`
- 期望结果：
  - 正确展示挂号确认弹窗
  - 向侧栏动作处理函数提交结构化参数
  - 参数至少包含 `department_name`、`doctor_id`、`doctor_name`
- 失败信号：
  - 无法弹出确认挂号
  - 点击确认后无动作
  - 提交参数缺失医生或科室信息

## Journey 8: 侧栏动作返回新 thread 后继续聊天

- Case ID: `FE-E2E-009`
- 页面：`chat_page.right_sidebar -> chat_page.center_panel`
- 优先级：`P0`
- 关联基线 case：`THREAD-005`、`SIDEBAR-001`
- 前置条件：
  - 当前已登录
  - 侧栏动作返回新的 `thread_id`
- 操作步骤：
  1. 触发右侧栏挂号确认动作
  2. 让服务端返回 `thread_id=server-thread-9`
  3. 在聊天输入框输入 `继续处理刚才那次挂号`
  4. 点击 `发送`
- 期望结果：
  - 页面把当前 thread 切换到 `server-thread-9`
  - 后续 `sendStream` 使用 `server-thread-9`
- 失败信号：
  - 侧栏返回的新 thread 未写入当前上下文
  - 后续聊天仍发往旧线程

## Journey 9: 删除线程成功

- Case ID: `FE-E2E-010`
- 页面：`thread_management`
- 优先级：`P1`
- 关联基线 case：`CHAT-005`
- 前置条件：
  - 当前已登录
  - 左侧存在待删除线程
  - `chatApi.deleteThread` 成功
- 操作步骤：
  1. 在左侧线程列表中点击删除按钮
  2. 确认删除
- 期望结果：
  - 线程从列表中消失
  - 线程对应消息从本地状态中移除
  - 若删除的是当前线程，则当前 thread 被清空
- 失败信号：
  - 服务端删除成功但 UI 仍保留旧线程
  - 当前线程被删后页面仍指向已不存在线程

## Journey 10: 删除线程失败时保留本地缓存并提示错误

- Case ID: `FE-E2E-011`
- 页面：`thread_management`
- 优先级：`P0`
- 关联基线 case：`THREAD-004`
- 前置条件：
  - 当前已登录
  - 左侧存在历史线程
  - 远端删除请求失败
- 操作步骤：
  1. 点击删除线程
  2. 确认删除
  3. 让 `chatApi.deleteThread` 返回错误
- 期望结果：
  - 线程仍保留在列表中
  - 页面提示 `删除失败，请稍后重试`
  - 本地消息缓存不被提前删除
- 失败信号：
  - 删除失败时线程仍被本地移除
  - 没有错误提示
