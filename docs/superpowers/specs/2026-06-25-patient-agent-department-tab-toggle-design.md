# patient_agent 科室 tab 二次点击取消选择设计

**日期：** 2026-06-25  
**范围：** `patient_agent_frontend` 医院排班模块的科室 tab 交互  
**状态：** 已确认

## 1. 背景

当前医院排班模块中的科室 tab 具备以下行为：

- 页面加载后会自动选中第一个有排班的科室
- 点击其他科室时，会切换当前科室摘要卡和医生排班列表
- 如果已打开挂号确认弹窗，切换科室时会自动关闭弹窗

现状中，当前已选中的科室 tab 再次点击时，不会发生任何变化。

用户本次新增需求是：

- 支持第二次点击当前已选中的科室 tab 后取消选择
- 取消选择后，医院排班区域显示空状态，而不是继续保留当前科室内容

## 2. 目标

### 2.1 交互目标

- 让科室 tab 支持“选中 / 取消选中”的双态交互
- 保持用户对当前状态的可理解性，不引入额外交互控件
- 不改变现有默认选中和切换科室的主路径

### 2.2 体验目标

- 用户可以主动收起当前科室内容，回到“未选择科室”的状态
- 取消选择后，页面语义清晰，提示用户重新选择科室
- 已有挂号流程在取消选择时也能保持一致收口

## 3. 已确认方案

本次已确认采用 `方案 A：已选 tab 再点一次直接取消`。

核心规则如下：

- 页面初始加载后仍自动选中第一个有排班的科室
- 如果用户点击的是当前未选中的科室，则正常切换
- 如果用户点击的是当前已选中的科室，则取消选择
- 取消选择后，显示医院排班空状态提示

## 4. 当前实现与约束

当前 `HospitalScheduleCard` 通过 `expandedDeptIndex` 表示当前选中的科室索引：

- `number`：表示当前有选中的科室
- `null`：表示当前没有选中科室

但在现有实现中：

- 页面初始会自动把 `expandedDeptIndex` 设为第一个有效科室
- tab 点击事件总是执行 `setExpandedDeptIndex(index)`
- 因此当前已选 tab 再点一次，仍保持选中状态，不会进入 `null`

这意味着本次改造无需增加新状态字段，只需要调整现有 `expandedDeptIndex` 的切换逻辑即可。

## 5. 交互设计

### 5.1 页面初始状态

页面加载完成后：

- 若存在有排班的科室，默认选中第一个有排班的科室
- 若没有任何可展示排班，则显示 `当前暂无可展示排班`

本次不修改这个默认激活逻辑。

### 5.2 点击未选中的科室 tab

当用户点击未选中的科室 tab 时：

- 切换为该科室选中状态
- 当前科室摘要卡更新为该科室内容
- 医生列表更新为该科室排班

这部分行为保持不变。

### 5.3 点击当前已选中的科室 tab

当用户点击的是当前已选中的科室 tab 时：

- 取消当前选中状态
- 将 `expandedDeptIndex` 设为 `null`
- 当前科室摘要卡消失
- 医生排班列表消失
- 显示空状态提示：`请选择科室查看今日排班`

这表示医院排班模块进入“未选择科室”的中性状态。

### 5.4 取消选择后的恢复

当模块处于未选择科室状态时：

- 用户点击任意科室 tab，可重新进入选中状态
- 当前科室摘要卡与医生列表正常恢复显示

因此交互闭环为：

- 默认选中
- 点击其他 tab 切换
- 再次点击当前 tab 取消
- 再次点击任意 tab 恢复

## 6. 弹窗联动规则

当前实现中，切换科室时会通过监听 `expandedDeptIndex` 变化关闭挂号确认弹窗。

本次取消选择也会触发：

- `expandedDeptIndex` 从某个索引变为 `null`

因此应继续沿用当前逻辑，保证：

- 若用户已打开挂号确认弹窗，再次点击当前科室 tab 取消选择时，弹窗同步关闭

这一点不需要新增单独逻辑，只需要保持现有副作用行为成立。

## 7. 可访问性与视觉一致性

本次不新增额外图标、复选标记或“清空选择”按钮。

视觉上保持当前 tab 样式规则：

- 已选中时沿用现有激活样式
- 取消后 tab 回到未激活样式
- 中间区域展示现有空状态卡片

这样可以避免额外视觉复杂度。

## 11. 风险与控制

### 11.1 风险点

- 如果初始自动选中逻辑与手动取消逻辑冲突，可能导致用户刚取消后又被自动选回去
- 如果 tab 的选中判断只改了视觉状态而没改内容状态，可能出现“未选中但内容还在”的不一致
- 如果取消选择未关闭弹窗，用户会看到与当前页面状态不一致的挂号确认框

### 11.2 控制策略

- 初始自动选中逻辑只在 `departments` 数据变化时触发，不在普通点击取消后重新触发
- 内容区域渲染继续以 `activeDepartment` 是否存在作为唯一依据
- 保持现有依赖 `expandedDeptIndex` 的弹窗关闭副作用
